## 第 5–6 格｜模型、损失、手工梯度

这是整节课的「发动机说明书」。先不要急着训练，把六个函数在黑板上对齐。

### 对照表：六个函数各管一段

| 函数 | 人话 | 公式 |
|------|------|------|
| `model` | 怎么从输入得到预测 | \(\hat{y}=wx+b\) |
| `loss_fn` | 预测和答案差多远 | \(\frac{1}{N}\sum(\hat{y}-y)^2\) |
| `dloss_fn` | 损失对每个预测的导数 | \(\frac{2}{N}(\hat{y}-y)\) |
| `dmodel_dw` | 预测对 `w` 的导数 | \(x\) |
| `dmodel_db` | 预测对 `b` 的导数 | \(1\) |
| `grad_fn` | 把上面接起来，得到 \(\partial L/\partial w,\partial L/\partial b\) | 链式法则 |

### 怎么讲 `model`

一行 `return w * inputs + b`。  
`w` 管斜率：未知读数多 1，预测摄氏度多多少。  
`b` 管截距：读数为 0 时预测多少。

`w` 是标量，`inputs` 是 11 个数，能直接相乘，靠的是 broadcasting。后面实验1会专门印形状，这里先埋一笔。

### 怎么讲 `loss_fn`

不是「错了几个点」，而是「每个点的误差平方后取平均」。  
平方有两个作用：负误差也变成正的；错得越远，惩罚越重。  
这个数必须能对 `w、b` 求导，我们才能顺着它下山。

### 怎么讲链式法则（对着 `grad_fn` 指）

请把屏幕上的三行念出来：

1. `dloss_dtp = dloss_fn(...)`  
   先问预测值：你偏高了还是偏低了？偏高就要把预测拉低。
2. `dloss_dw = dloss_dtp * dmodel_dw(...)`  
   预测是 `w*x+b`，`w` 乘在 `x` 上，所以要把「预测该怎么变」再乘上 `x`，才能告诉 `w`。
3. `dloss_db = dloss_dtp * 1`  
   `b` 是直接加进去的，预测怎么变，`b` 就怎么变。
4. 最后 `.sum()`  
   11 个点各有一份意见，加总成两个数：对 `w` 的梯度、对 `b` 的梯度。

**口诀：** 损失先骂预测，预测再骂参数。深度网络只是把「预测」中间插入更多层，骂声一层层往回传。这就是后来 `backward()` 做的事。

### `del w, b` 是什么

这两个函数的导数碰巧不依赖 `w、b` 本身，但函数签名仍留下它们，方便和 `model` 对照。`del` 只是告诉读者：这里故意不用这两个参数。课堂上提一句即可，不要展开。

**这格运行后没有训练输出，只有定义。** 告诉学生：现在发动机装好了，还没点火。

## 第 7–8 格｜三种训练循环

**这是对照讲解的核心。请把四个函数在投影上并排理解，不要逐行念完。**

四个循环不是四套算法，是同一件事情的四种写法。

### 总对照

| 循环 | 对应实验 | 求梯度 | 改参数 | 是否算验证损失 |
|------|----------|--------|--------|----------------|
| `manual_training_loop` | 实验1 | `grad_fn` 手算 | `params - lr * grad` | 否 |
| `autograd_training_loop` | 实验2 | `loss.backward()` | 仍手写减法 | 否 |
| `optimizer_training_loop` | 实验3 前半 | `loss.backward()` | `optimizer.step()` | 否 |
| `train_validation_loop` | 实验3 后半 | 只对训练损失 `backward` | `optimizer.step()` | 是 |

请学生用手指跟上：**从左到右，人干的活越来越少，框架接的活越来越多。但圈还是那一圈：前向 → 损失 → 梯度 → 更新。**

### 对着 `manual_training_loop` 讲「最原始的一圈」

循环体只有四句有效代码：

```text
predictions = model(...)
loss = loss_fn(...)
grad = grad_fn(...)
params = params - learning_rate * grad
```

这就是梯度下降。没有 PyTorch 魔法。

另外三处是教学习惯：

- `params.clone()`：拷一份再改，避免把外面传入的张量偷偷改掉
- `report_epochs`：只在关键轮次打印，否则 5000 行刷屏
- `torch.isfinite`：loss 一旦变成 `inf/nan` 立刻停。对照 A 就会走到这里

### 对着 `autograd_training_loop` 讲「换掉求梯度」

和上一格并排看，只换了中间两步：

- 原来：`grad = grad_fn(...)`
- 现在：先 `params.grad.zero_()`，再 `loss.backward()`，梯度出现在 `params.grad` 里

更新仍是：

```python
with torch.no_grad():
    params -= learning_rate * params.grad
```

这里必须停下来讲两点。

**第一，为什么每次都要清零。**  
PyTorch 默认把梯度累加。不清零，第二次反传会叠在第一次上，等于方向被污染。标准训练循环里，每次更新前都必须清。

**第二，为什么更新要包 `no_grad`。**  
`params` 开了 `requires_grad=True`。若普通减法，这次「改参数」也会被记进计算图，图会越来越长。改参数只是改数值，不是还要对这次改动再求导。所以暂时关掉追踪。

`params.clone().detach().requires_grad_()` 这串也很值得指一下：

- `clone`：拷贝
- `detach`：切断和旧计算图的关系
- `requires_grad_()`：从现在起，新图要追踪它

### 对着 `optimizer_training_loop` 讲「再换掉更新」

经典四句终于出现：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

对照上一格：

- `zero_grad()` 替代 `params.grad.zero_()`
- `step()` 替代 `params -= lr * params.grad`

**SGD 的 `step()` 几乎就是我们手写的那一次减法。** Adam 的 `step()` 更复杂，会自适应步长，但对外接口一样。所以实验3才能用同一个循环函数，只换 optimizer 对象。

### 对着 `train_validation_loop` 讲「训练能学，验证只能看」

每个 epoch 算两次损失：

- `train_loss`：用来 `backward` 和 `step`
- `val_loss`：只记录，不反传

`use_no_grad` 是开关：

- `False`：验证前向也建计算图。结果仍对，因为反传的是训练损失；只是浪费
- `True`：验证包在 `torch.no_grad()` 里，并 `assert val_loss.requires_grad is False`

**原则就一句：验证数据可以看，不能学。**

这格同样只是定义函数。告诉学生：四种发动机都在停车场里了，下面开始上路。

### 第二段：broadcasting

这段不是主线，约 1 分钟。目的是让学生以后看到奇怪的形状相乘，知道这是特性不是 bug。

---

### 第三段：有限差分 vs 解析梯度

先讲人话：不会求导时，就把 `w` 加一点点、减一点点，看损失怎么变。这叫中心有限差分：

\[
\frac{\partial L}{\partial w} \approx \frac{L(w+\delta)-L(w-\delta)}{2\delta}
\]

\(\delta=0.1\)。得到近似梯度后，立刻做一次：

```text
w ← w - 0.01 * (dL/dw)
```

对 `b` 再来一次。

然后代码调用 `grad_fn`，打印解析梯度。

**对照怎么讲：**

- 数值法：好懂，但每个参数都要额外算两次损失。百万参数时不可能
- 解析法：一次前向就能得到精确梯度
- 两者方向应接近，数值不必完全相同。因为有限差分是近似，而且这里还先更新了 `w` 再去估 `b`，解析梯度是在更新后的点上算的

**收束：** 梯度的本质就是「参数动一点点，损失怎么变」。后面 `backward()` 只是把这件事自动化。

## 第 13–14 格｜实验2：autograd

运行第 14 格前，先把第 13 格的提醒读出来：更新仍是手工的；反传前必须清零。

### 先看「三次打印」，不要直接看 5000 轮

1. `backward前 params.grad is None: True`  
   还没反传，PyTorch 不知道梯度。`None` 不是 0，是「不存在」。

2. 做完 `loss.backward()` 后，`params.grad` 里出现两个数  
   这就是 \(\partial L/\partial w\) 和 \(\partial L/\partial b\)。它应和实验1里 `grad_fn` 的思想一致，只不过现在没人手写链式法则。

3. `zero_()` 之后，梯度变成 0  
   清的是梯度，不是参数。`params` 本身还是 `[1, 0]`。学生很容易把这两件事混在一起，这里要单独点破。

**对照口令：**

- `backward()`：只负责把梯度写进 `.grad`，参数还没动
- 后面的减法或 `step()`：才真正改 `w、b`

### 再看 5000 轮 autograd 训练

设置故意和实验1完整拟合对齐：归一化输入、`lr=1e-2`、5000 轮、初值 `[1, 0]`。

每 500 轮打一次 loss。趋势应和实验1很像：稳定下降并收敛。最终 `w, b` 存进 `autograd_params`。

**对照句，请原话讲：**

> autograd 不是另一种学习算法。它只是用同一条链式法则，把我们在实验1手算的导数自动算出来。所以两者应该学到几乎同一条直线。

最后一格会用数字验证这句话。

### 第一段：优化器清单

打印 `SGD、Adam、RMSprop...` 即可。  
告诉学生：`torch.optim` 是一个工具箱，不同优化器是不同的「下山策略」。今天只用 SGD 和 Adam。接口相同，内部规则不同。

### 第二段：两次「单步更新」

**第一次：** 原始 `t_u` + SGD + 很小的 `lr=1e-5`，而且**没写** `zero_grad()`。  
目的：证明 `step()` 真的会改 `params`。请看打印出来的 `w, b`，已经不是 `[1, 0]`。  
学习率故意很小，因为原始输入上 SGD 一步太大容易乱跑。这里只走一步，观察即可。

**第二次：** 归一化输入 + `lr=1e-2` + 标准顺序 `zero_grad → backward → step`。  
告诉学生：这才是以后要默写的顺序。第一次省略 `zero_grad` 是因为刚创建、梯度还是空的，碰巧能跑；养成习惯必须每次都写。

**对照：** 实验2里人手写 `params -= lr * grad`；这里一行 `step()` 替代了它。SGD 时两者几乎是同一件事。

---

### 第三段：SGD 5000 轮 vs Adam 2000 轮

**SGD：** `t_un` + `lr=1e-2` + 5000 轮。  
应收敛到和实验1、2相近的参数。这是第三种实现，同一条直线。

**Adam：** 故意喂原始 `t_u`，学习率 `0.1`，只跑 2000 轮。也能拟合。

**对照一定要讲公平：**

- 不是「Adam 更强所以赢了」
- 是「Adam 会按梯度历史自适应调整有效步长」，对输入尺度没那么娇气
- SGD 很老实，输入大、学习率大，照样会炸，所以我们给它归一化
- 工程上通常仍要归一化；Adam 不是免死金牌

若课堂时间紧，Adam 段可以只看最终 `params`，不解释矩估计。

### 第四段：划分训练 / 验证

11 个点，`int(0.2 * 11) = 2`，大约 9 个训练、2 个验证。  
`torch.randperm` 打乱后再切。因为前面固定了种子，全班下标应一致。

请把打印的 `train_indices`、`val_indices` 指给学生看：两类下标没有重叠。这叫 **independent**，独立样本。

然后各自再乘 `0.1` 得到 `train_t_un`、`val_t_un`。归一化要对训练和验证用同一规则。不能只用训练集的统计量去「偷看」验证集——本实验只是乘常数，没有这个问题，但习惯要先说清楚。

**为什么必须拆开：**  
若 11 个点既训练又打分，模型越拟合，分数越好看，那是在背答案。验证集模拟「没见过的温度读数」。

**预先打预防针：** 验证只有 2 个点，曲线会抖，甚至偶尔比训练损失还低。这不代表模型神奇，只代表样本太少、偶然性大。真实项目验证集要大得多。

### 第五段：实验 A / B 与 `set_grad_enabled`

两组都训练 3000 轮，数据相同，差别只有验证前向是否建图。

**实验 A：`use_no_grad=False`**  
验证损失也会进入计算图。但 `backward()` 仍然只对 `train_loss` 调用，所以学到的参数应和 B 几乎一样。A 的意义是「能跑，但不推荐」。

**实验 B：`use_no_grad=True`**  
验证包在 `no_grad` 里。输出里每个 epoch 的 training loss 和 validation loss 会一起出现。最后一张图从这里生成。

**读图4：**

- 两条是否都在降？降说明在学，而且对没见过的点也还过得去
- 验证曲线是否更抖？2 个点，正常
- 不要看到验证损失低于训练损失就欢呼。样本少时完全可能

**最后的 `calc_forward`：**  
真实项目不想把训练前向和验证前向写成两份。于是用一个开关：

```python
with torch.set_grad_enabled(is_train):
    ...
```

打印应是：

- `train requires_grad=True`：后面可以 `backward`
- `val requires_grad=False`：只是一个普通数字

两个 `assert` 通过，说明开关有效。

**对照三种关梯度的方式：**

| 写法 | 典型用途 |
|------|----------|
| `with torch.no_grad():` | 整段验证/推理 |
| `tensor.detach()` | 切断某个张量和计算图的关系 |
| `torch.set_grad_enabled(flag)` | 训练/验证共用一个前向函数 |

课堂上记住前一种和第三种即可。

## 第 17–18 格｜最终对照：手工 vs autograd

第 17 格只有标题。运行第 18 格。

它计算：

```text
max |手工参数 - autograd参数|
```

要求这个数小于 `1e-4`。通过就会打印「所有实验完成，且全过程仅使用CPU」，并列出四张图的文件名。

**这是整节课的句号，请讲透：**

实验1 的 `manual_params` 和实验2 的 `autograd_params`，起点一样、数据一样、学习率一样、轮数一样。若 autograd 偷偷换了算法，两者对不上。现在对上了，说明：

> 自动求导 = 我们手写的链式法则。  
> 优化器里的 SGD = 我们手写的 `参数减去学习率乘梯度`。  
> 所谓深度学习训练循环，没有第三种神秘力量。

若这里 `assert` 失败，优先检查：有没有改过学习率、有没有用错 `t_u` / `t_un`、实验1和实验2是不是都跑完了。笔记本必须按顺序运行，因为后面的格依赖前面的变量。

## 对着笔记本可现场问的问题

讲到哪一格，就问哪一句。不要集中到最后。

1. **第4格：** `t_un` 是新数据吗？  
   不是。同一支温度计，只是读数乘了 0.1。

2. **第6格：** 为什么损失要平方？  
   正负误差都惩罚；大误差惩罚更重；并且可导。

3. **第8格：** `manual` 和 `autograd` 两个循环，哪一行不一样？  
   求梯度那一行：`grad_fn` 换成 `backward`。

4. **第12格对照A：** 是模型错了吗？  
   模型没错，是步子太大。

5. **第14格：** `grad` 变成 0 之后，`w` 变了吗？  
   没有。清的是梯度，不是参数。

6. **第16格：** 为什么验证损失不能 `backward`？  
   一反传，验证集就泄漏进训练，分数会骗人。

7. **第18格：** 差小于 `1e-4` 说明什么？  
   说明自动求导没有另搞一套数学，只是替我们算了同一条链式法则。

## 一、这节课到底在讲什么

很多同学第一次写神经网络时，会看到这样一段代码：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

这三行几乎出现在所有深度学习程序里。如果只背下来，后面遇到 loss 不降、训练发散、显存暴涨、验证集用法不对，仍然会一头雾水。

**这节课的任务，就是把这三行拆开，亲手做一遍。**

我们不用复杂网络，只用一个最简单的线性模型：

\[
\hat{y} = w \cdot x + b
\]

只有两个要学的数：斜率 \(w\) 和截距 \(b\)。因为模型足够小，每一步发生了什么都能算清楚、打印出来、画成图。

学完后，学生应能回答：

1. 什么是参数、预测、损失、梯度？
2. 为什么损失能指导参数更新？
3. 学习率太大为什么会炸？输入为什么常常要归一化？
4. `autograd` 到底替我们做了什么？
5. `optimizer` 又替我们做了什么？
6. 为什么要有验证集？验证时为什么要关掉梯度？

## 二、用一个故事把问题讲清楚

### 2.1 未知温标的温度计

想象桌上有一支旧温度计，刻度不是摄氏度。我们同时用一支可靠的摄氏温度计做对照，记下了 11 组数据：

| 含义 | 符号 | 例子 |
|------|------|------|
| 未知温标读数 | `t_u` | 35.7, 55.9, 58.2, … |
| 真实摄氏度 | `t_c` | 0.5, 14.0, 15.0, … |

我们怀疑两者之间接近一条直线：

\[
t_c \approx w \cdot t_u + b
\]

如果能找到合适的 \(w\) 和 \(b\)，以后只看未知温度计，也能换算出摄氏度。

这就是机器学习里最经典的设定：

- **输入** \(x\)：未知读数 `t_u`
- **目标** \(y\)：摄氏度 `t_c`
- **模型**：带参数的函数
- **学习**：根据数据自动找到参数

### 2.2 为什么不直接用公式解

两点可以精确确定一条直线，但我们有 11 个点，而且有噪声，不可能所有点都完美落在同一条直线上。所以不是「解方程」，而是「找一条尽量贴近这些点的直线」。

「尽量贴近」需要一个打分标准，这就是 **损失（loss）**。

## 三、先建立四个核心概念

讲授时建议在黑板上画一条流水线，后面所有代码都对应这四个格子：

```text
输入 x  -->  模型(w, b)  -->  预测 ŷ  -->  和真实 y 比较  -->  损失 L
                                              ↑
                                    用梯度告诉 w、b 该怎么改
```

### 3.1 模型：怎么从输入得到预测

代码里的模型只有一行：

```python
def model(inputs, w, b):
    return w * inputs + b
```

含义：

- `w` 控制「未知读数每增加 1，预测摄氏度增加多少」
- `b` 控制「未知读数为 0 时，预测摄氏度是多少」

一开始我们故意设得很差：

- `w = 1`
- `b = 0`

也就是假设「未知读数直接等于摄氏度」。这显然不对，因为 `t_u` 大约是 20～80，而 `t_c` 大约是 -4～28。用这个初始模型去预测，误差会很大。实验会把这个「一开始有多差」打印出来。

### 3.2 损失：怎么衡量「差得有多远」

本实验用 **均方误差 MSE**：

\[
L = \frac{1}{N}\sum_{i=1}^{N}(\hat{y}_i - y_i)^2
\]

白话版：

1. 每个点算出「预测值减真实值」
2. 平方，让正负误差都变成正数，并且大误差会被放大
3. 对所有点取平均，得到一个数

这个数越小，直线拟合得越好。

**一定要强调：** 损失不是给人类看的分数那么简单，它必须对参数可导，我们才能用梯度下降去减小它。

### 3.3 梯度：告诉参数「往哪边改、改多少」

把损失看成一座山，\(w\) 和 \(b\) 是你在山上的位置。梯度就是这座山最陡的上坡方向。

要下山（减小损失），就应该 **沿着梯度的反方向走一小步**：

\[
w \leftarrow w - \eta \cdot \frac{\partial L}{\partial w}
\]

\[
b \leftarrow b - \eta \cdot \frac{\partial L}{\partial b}
\]

这里的 \(\eta\) 就是 **学习率 learning rate**。

可以这样记：

- 梯度为正：说明把这个参数再增大，损失会更大，所以应该减小它
- 梯度为负：说明把这个参数再增大，损失会变小，所以应该增大它
- 学习率：这一步迈多大

### 3.4 训练循环：把上面的事重复很多遍

一次更新叫一个 **epoch**（本实验数据很少，每个 epoch 用全部 11 个点）。完整循环永远是：

1. 前向：用当前 `w, b` 做预测
2. 算损失
3. 算梯度
4. 用梯度和学习率更新参数
5. 再回到第 1 步

深度学习后来再复杂，本质上还是这一圈。

## 四、实验1：亲手算梯度，看学习是怎么发生的

这是整节课最重要的一块。建议课堂时间 recap 时占一半。

### 4.1 先看初始模型有多差

代码用 `w=1, b=0` 对原始 `t_u` 做预测。学生会看到：

- 预测值大约是 35、55、58……
- 真实值却是 0.5、14、15……
- 初始 MSE 会非常大

**讲授点：** 模型结构对了不等于会预测。还没学习时，参数几乎是瞎猜。

### 4.2 顺手认识 broadcasting（广播）

实验里插了一小段不同形状 Tensor 相乘：

- 标量 `x`，形状 `()`
- `y` 形状 `(3, 1)`
- `z` 形状 `(1, 3)`
- `a` 形状 `(2, 1, 1)`

PyTorch 会自动把能对齐的维度「拉齐」再运算，所以：

- `x * y` 还是 `(3, 1)`
- `y * z` 变成 `(3, 3)`
- `y * z * a` 变成 `(2, 3, 3)`

**为什么要在这里讲：** 后面模型写的是 `w * inputs + b`。`w`、`b` 常常是标量，`inputs` 是一串数。全靠 broadcasting，才不用写 for 循环。学生以后写神经网络，几乎处处都在用它。

课堂只需强调一条规则：从右往左看维度，要么相等，要么有一方是 1，要么有一方没有这一维。

### 4.3 第一种求梯度的办法：有限差分（数值法）

先不要讲公式求导。问学生：如果我不会求导，怎么知道损失对 `w` 敏不敏感？

办法很朴素：把 `w` 稍微加大一点，再稍微减小一点，看损失怎么变。

\[
\frac{\partial L}{\partial w} \approx \frac{L(w+\delta) - L(w-\delta)}{2\delta}
\]

本实验取 \(\delta = 0.1\)。这叫 **中心有限差分**。

得到近似的 \(\partial L/\partial w\) 后，立刻做一次更新：

```text
w ← w - 0.01 * (dL/dw)
```

对 `b` 再做一遍。

**讲授点：**

- 梯度的本质是「参数动一点点，损失怎么变」
- 数值法好懂，但每个参数都要额外算两次损失。模型有百万参数时，这样求梯度完全不现实
- 所以后面必须换成解析梯度，再换成 `autograd`

### 4.4 第二种求梯度的办法：链式法则（解析法）

模型是：

\[
\hat{y} = w x + b
\]

损失是：

\[
L = \frac{1}{N}\sum (\hat{y}_i - y_i)^2
\]

先看损失对某一个预测值的导数：

\[
\frac{\partial L}{\partial \hat{y}_i} = \frac{2}{N}(\hat{y}_i - y_i)
\]

这就是代码里的 `dloss_fn`。

再看模型对参数的导数：

\[
\frac{\partial \hat{y}}{\partial w} = x, \qquad \frac{\partial \hat{y}}{\partial b} = 1
\]

这就是 `dmodel_dw` 和 `dmodel_db`。

链式法则把两段接起来：

\[
\frac{\partial L}{\partial w} = \sum_i \frac{\partial L}{\partial \hat{y}_i} \cdot x_i
\]

\[
\frac{\partial L}{\partial b} = \sum_i \frac{\partial L}{\partial \hat{y}_i} \cdot 1
\]

这就是 `grad_fn`。

**课堂上可以用一句话收束：**  
「损失先告诉预测值该变大还是变小；预测值再告诉 `w` 和 `b` 该变大还是变小。」

深度网络无非是把「预测值」中间插入更多层，链式法则一层层往回传。这就是后来 `backward()` 在做的事。

### 4.5 手工训练循环长什么样

`manual_training_loop` 把解析梯度接到更新公式上：

```text
预测 = w * x + b
损失 = MSE(预测, 真实值)
梯度 = 手工链式法则
参数 = 参数 - 学习率 * 梯度
```

没有 `backward()`，没有 `optimizer`。学生必须先过这一关，后面两段才不显得像魔法。

如果损失变成 `inf` 或 `nan`，循环会主动停。这是在保护「学习率过大导致数值爆炸」的情况。

### 4.6 三组对照：这是本实验最精彩的现象

同一套手工训练，只改学习率和输入尺度，结果完全不同。

#### 对照 A：原始输入 + 学习率 `1e-2`

`t_u` 本身大约是几十。梯度 \(\partial L/\partial w\) 里乘过这些较大的 \(x\)，所以梯度很大。再乘 `0.01`，一步就迈得太远，直接冲到山谷对面，甚至冲出合理范围。

学生会看到 loss 迅速变成天文数字，然后出现非有限损失，循环停止。

**结论：学习率不是越大越好。步子太大，会从山坡上摔下去。**

#### 对照 B：原始输入 + 学习率 `1e-4`

把学习率缩小 100 倍。现在能稳住，loss 会下降，但 100 个 epoch 后仍然降得很慢。

**结论：学习率太小，也能学，但像蜗牛爬山。**

#### 对照 C：归一化输入 + 学习率 `1e-2`

代码做的归一化非常简单：

```python
t_un = 0.1 * t_u
```

只是把输入缩小 10 倍，例如 55.9 变成 5.59。输入小了，对 `w` 的梯度也小了，原来会炸的 `1e-2` 现在刚好合适，loss 下降又稳又快。

**这是必须讲透的一点：**

不是模型变了，也不是损失变了，只是输入的数值范围变了，梯度的尺度就变了，同样的学习率就从「致命」变成「刚好」。

以后训练神经网络时：

- 图像像素常除以 255
- 表格特征常做标准化
- 原因都在这里

### 4.7 完整拟合 5000 轮

确认对照 C 有效后，用归一化输入、学习率 `1e-2`，从 `[w, b] = [1, 0]` 开始跑 5000 轮。

学生应看到：

- 前几轮 loss 明显下降
- 后面下降变慢，逐渐收敛
- 最终得到一组稳定的 `w, b`
- 拟合直线会穿过那 11 个点的主体趋势

物理上，这条直线就是「未知温标 → 摄氏度」的换算关系。数值上，它是梯度下降找到的 MSE 最优近似。

### 4.8 实验1结束后学生应记住的三句话

1. 学习 = 用损失的梯度反复改参数。
2. 学习率控制步长，太大发散，太小太慢。
3. 输入尺度会改变梯度尺度，所以常常先归一化。

## 五、实验2：让 autograd 替我们求导

实验1证明：梯度可以手算。但手算只适合 `w*x+b`。网络一深，手工链式法则会写崩。

PyTorch 的 `autograd` 做的事情就是：**你写前向公式，它自动帮你反向求导。**

### 5.1 先看 `requires_grad` 和 `.grad`

实验一开始故意演示三件事：

1. 创建

   ```python
   params = torch.tensor([1.0, 0.0], requires_grad=True)
   ```

   此时 `params.grad` 是 `None`。还没反向传播，PyTorch 不知道梯度。

2. 做一次前向，算 loss，然后：

   ```python
   loss.backward()
   ```

   现在 `params.grad` 里出现了两个数，分别是 \(\partial L/\partial w\) 和 \(\partial L/\partial b\)。

3. 立刻

   ```python
   params.grad.zero_()
   ```

   梯度被清成 0。

**课堂一定要停下来问：** 为什么要清零？

因为 PyTorch **默认把梯度累加**。如果不清零，第二次 `backward()` 会把新梯度加到旧梯度上。这不是 bug，而是设计：有时一个 batch 太大，会分几次反传再一次性更新。但对我们这个标准循环，每次更新前都必须清零。

### 5.2 autograd 版训练循环和手工版差在哪

手工版：

```text
grad = grad_fn(...)          # 人写链式法则
params = params - lr * grad  # 人写更新
```

autograd 版：

```text
loss.backward()              # 框架写链式法则
params -= lr * params.grad   # 人仍然写更新
```

注意：实验2 **没有使用 optimizer**。它只替换了「求梯度」这一步，更新公式还是我们自己写。

这样安排是有教学意图的：

- 实验1：梯度也自己算，更新也自己做
- 实验2：梯度交给框架，更新自己做
- 实验3：梯度和更新都交给框架

一层层把魔法拆掉。

### 5.3 为什么更新时要包 `torch.no_grad()`

```python
with torch.no_grad():
    params -= learning_rate * params.grad
```

因为 `params` 开了 `requires_grad=True`。如果直接

```python
params = params - lr * params.grad
```

这次减法本身也会被记进计算图，图会越来越长，又慢又容易出错。

更新参数只是「改数值」，不是「还要对这次改动再求导」。所以要暂时关掉梯度追踪。

### 5.4 关键对照：手工梯度 vs autograd

实验最后会比较两组最终参数，要求最大绝对差小于 `1e-4`。

**这是整节课的「信任证据」：**  
不是 autograd 换了一套学习算法，它只是用同一条链式法则，把我们手算的导数自动算出来。所以两者应该收敛到几乎同一组 `w, b`。

如果学生问「那以后还要手写 `grad_fn` 吗？」答案是：理解原理时要会，工程上几乎不用。

## 六、实验3：optimizer、验证集、梯度开关

到这里，学生已经会「自动求导 + 手工更新」。真正项目里，更新也交给 `torch.optim`。

### 6.1 optimizer 是什么

可以把它理解成「专门负责改参数的管家」。

你告诉它：

- 要管哪些参数：`[params]`
- 用什么规则改：`SGD` 还是 `Adam`
- 学习率是多少

然后每个循环只做四件事：

```python
predictions = model(...)
loss = loss_fn(...)
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

对应关系：

| 代码 | 含义 |
|------|------|
| 前两行 | 前向，得到损失 |
| `zero_grad()` | 把上一次的梯度清掉 |
| `backward()` | 自动求导，把梯度写入 `.grad` |
| `step()` | 按优化器规则更新参数 |

**强调顺序：** 必须先清零，再反传，再更新。写反是新手高频错误。

### 6.2 先做「单步更新」再做完整训练

实验先让学生看一次 `step()` 之后 `params` 真的变了。不要一上来就跑 5000 轮。先建立直觉：optimizer 不是黑盒，它就是在改 `w` 和 `b` 这两个数。

接着：

- **SGD + 归一化输入 + 学习率 1e-2 + 5000 轮**
- **Adam + 原始输入 + 学习率 1e-1 + 2000 轮**

这里有一个非常好的对比：

**SGD 很「老实」。** 每一步就是 `参数 -= 学习率 * 梯度`。所以它对输入尺度和学习率仍然敏感。原始输入太大时，SGD 通常还是要配更小学习率，或者先归一化。本实验给 SGD 用的是归一化输入。

**Adam 会自适应调整每个参数的有效步长。** 对尺度不那么娇气，所以实验故意让它直接吃原始 `t_u`，学习率还可以用到 `0.1`，2000 轮也能拟合得不错。

**不要讲成「Adam 一定比 SGD 强」。** 这里只说明：优化器会改变「同样数据、同样模型」时的学习稳定性。学生以后选优化器，本质是在选更新规则。

### 6.3 为什么要有验证集

如果只用这 11 个点训练，又用这 11 个点评价，模型当然可以越拟合越好看。但我们真正关心的是：**没见过的温度读数，还能不能换算对。**

所以要把数据拆开：

- **训练集**：用来算梯度、更新参数
- **验证集**：只用来打分，不参与更新

本实验大约按 80% / 20% 划分。11 个点里验证集大约 2 个。数量很少，所以验证曲线会比较抖，这正好可以提醒学生：验证集太小时，分数会不稳定。真实项目里验证集要大得多。

划分前用固定随机种子打乱，保证可复现。

**讲授时一定要说清楚：**

- 训练损失下降，只说明模型在「背」训练样本
- 验证损失下降，才说明学到了可推广的规律
- 若训练损失继续降、验证损失开始升，就是过拟合

本实验模型极简、数据也少，未必能看到典型过拟合拐弯。重点是让学生建立「两套损失分开看」的习惯。

### 6.4 只用训练损失反传

`train_validation_loop` 里虽然每个 epoch 都算了验证损失，但 `backward()` 只对 `train_loss` 调用。

这是原则：

> 验证数据可以看，不能学。

如果对验证损失也 `backward()`，验证集就泄漏进训练，评估会虚高。

### 6.5 对照 A/B：验证前向要不要建计算图

每次前向只要涉及 `requires_grad=True` 的参数，PyTorch 默认都会把运算记下来，形成一个计算图，准备以后 `backward()`。

但验证集根本不会 `backward()`。建图纯属浪费。

于是实验做了两组：

- **实验 A：** 验证前向也建图。结果仍然正确，因为最后反传的是训练损失。只是多花内存和时间。
- **实验 B：**

  ```python
  with torch.no_grad():
      val_loss = ...
  ```

  验证损失的 `requires_grad` 为 `False`。代码里还有 `assert` 帮助学生确认。

**对学生的实用口令：**

- 训练：需要梯度
- 验证 / 测试 / 单纯推理：关掉梯度

大模型上，这能省很多显存。

### 6.6 `set_grad_enabled`：把训练和验证写成同一个函数

真实项目里，人们常把「前向 + 算损失」抽成一个函数。这时不想写两套代码，只想传一个开关：

```python
def calc_forward(inputs, targets, is_train):
    with torch.set_grad_enabled(is_train):
        predictions = model(inputs, *params)
        return loss_fn(predictions, targets)
```

- `is_train=True`：建图，损失带梯度，后面可以 `backward()`
- `is_train=False`：不建图，损失只是一个普通数字

实验最后用 `assert` 检查这两种情况。这不是考试刁难，而是在教一种工程习惯：训练和验证可以共用前向函数，但梯度开关必须分开。

## 七、四张图怎么带学生读

运行后会在 `outputs/` 下生成四张图。授课时不要只说「看，拟合成功了」，而要带着读图。

### 图1 `01_temperature_data.png`

### 图3 `03_learning_rate_comparison.png`

纵轴常用对数，因为发散时损失会暴涨。

- 原始输入 + `1e-2`：曲线很快消失或冲上天，对应对照 A
- 原始输入 + `1e-4`：下降，但慢，对应对照 B
- 归一化 + `1e-2`：又稳又快，对应对照 C

这张图是实验1的「证据照片」，建议投影停留久一点。

### 图4 `04_train_validation_loss.png`

1. 两条是否都在下降？
2. 验证损失是否明显高于训练损失？

## 八、三个实验如何串成一条主线

建议用下面这张表收束整节课：

| 实验 | 梯度谁来算 | 参数谁来更新 | 额外教学点 |
|------|------------|--------------|------------|
| 实验1 | 人手写链式法则 | 人手写 `params -= lr * grad` | 学习率、归一化、有限差分 |
| 实验2 | `loss.backward()` | 人手写更新，并 `no_grad` | `requires_grad`、`.grad`、清零 |
| 实验3 | `loss.backward()` | `optimizer.step()` | SGD/Adam、训练验证划分、梯度开关 |

同一组温度数据，同一套线性模型，三种实现应学到相近的直线。最后脚本还会检查：手工梯度与 autograd 的参数差要小于 `1e-4`。

这能把学生从「会调用 API」拉回到「知道 API 在替代哪一步」。

## 九、课堂上建议强调的结论

1. **深度学习的学习，不是死记样本，而是改参数。** 参数改对了，新输入也能预测。
2. **损失是指南针，梯度是方向，学习率是步长。** 三者缺一不可。
3. **输入的数值范围会改变梯度大小。** 归一化常常比盲目调学习率更有效。
4. **`autograd` 不是另一种算法，只是自动的链式法则。**
5. **每次反传前要 `zero_grad()`。** 梯度默认会累加。
6. **`optimizer.step()` 只是把更新规则打包。** SGD 接近我们手写的那一步；Adam 更自适应。
7. **训练损失用于学习，验证损失用于检查有没有学会「举一反三」。**
8. **不需要梯度时就关掉。** `no_grad` / `set_grad_enabled(False)` 是为了正确和省资源。

## 十、学生容易错的地方（可作课堂提问）

**问：损失越小越好，那我把学习率开到 1 会不会学得更快？**  
答：不一定。对照 A 就是反例。太大直接发散。

**问：既然 Adam 能吃原始输入，是不是以后都不用归一化？**  
答：不是。归一化通常仍有帮助，训练更稳、超参更好找。Adam 只是没那么脆弱。

**问：验证损失也是损失，为什么不一起反传，让它也变小？**  
答：那样验证集就不再「没见过」。分数会骗人。

**问：`backward()` 之后为什么参数还没变？**  
答：`backward()` 只负责把梯度写进 `.grad`。真正改参数的是后面的减法或 `optimizer.step()`。

**问：为什么更新参数时还要 `no_grad`？**  
答：改参数是改数值，不是一次还要再求导的运算。继续追踪会把计算图越积越长。

**问：本实验只有 11 个点，能说明神经网络吗？**  
答：能说明学习机制。复杂网络只是把 `w*x+b` 叠得更深、参数更多，循环结构不变。

## 十二、课后思考题（可留给学生）

1. 如果把归一化从 `0.1 * t_u` 改成 `0.01 * t_u`，同样用 `lr=1e-2`，训练会变快、变慢，还是可能学不动？为什么？
2. 实验2如果去掉 `params.grad.zero_()`，连续训练 10 轮，梯度会怎样变化？
3. 为什么验证集前向关掉梯度，最终学到的 `w, b` 仍应和开着梯度时几乎一样？
4. 若验证损失明显低于训练损失，一定说明模型很好吗？结合本实验样本数回答。
5. 用自己的话写出标准训练四步，并标明每一步对应实验1、2、3中的哪一段代码。

参考答案要点：

1. 输入再缩小 10 倍，对 `w` 的梯度也更小，同等学习率下更新变慢，像对照 B；不一定发散，但可能很久才收敛。`w` 的最终数值也会大约变大 10 倍，因为要补偿输入被缩小。
2. 梯度会累加，更新方向被放大、被污染，训练会乱。
3. 验证前向是否建图，不改变训练损失的反传，因此参数更新相同；差别主要在速度和内存。
4. 不一定。验证集只有约 2 个点时，分数偶然性很大。
5. 前向 → 损失 → 反传/求梯度 → 更新。实验1全手工；实验2用 `backward` 替换求梯度；实验3再用 optimizer 替换更新。

## 十三、讲授时可用的最短口诀

可以让学生下课前齐声过一遍：

> 前向出预测，预测对目标，目标生损失，损失反传成梯度，梯度乘学习率，减去后参数更新。  
> 训练才建图，验证要关掉。  
> 步子太大就飞出去，输入太大先缩小。

这节课成功的标志不是学生能背出函数名，而是能指着那三行经典代码说：

- `zero_grad()`：把旧方向清掉
- `backward()`：自动做我在实验1里手写的链式法则
- `step()`：按优化器规则走一步，相当于我在实验1、2里写的 `params -= lr * grad`

能讲到这一层，学习机制就算真正进头脑了。
